03模块用途 × 重点分级

学之前先知道“这东西以后在哪用”，记忆效率会高很多。优先级按找工作 + 实际开发综合排序。

分级说明： 必掌握 写不出就等于不会 SQL； 重要 工作常见，需要会用； 了解 知道概念和用途即可； 面试高频 不一定天天写，但面试爱问。

04速查手册：DDL / DML / DQL

按“忘了一眼就能想起来”的标准写，示例基于黑马配套的 emp / dept / salgrade 三张表。建议打印出来放在手边。

关于示例字段：基础篇的 emp 表只含工号、姓名、性别、年龄、身份证、地址、入职日期；到多表查询章节会补上 dept_id，部分版本还含 salary。本文示例默认 emp 已有 salary、dept_id， 跟练前先执行 alter table emp add salary decimal(10,2), add dept_id int;，或直接使用课程配套的完整脚本。

DDL · 定义数据库和表

建库、建表、改表结构
-- 1. 数据库
create database if not exists db_study default charset utf8mb4;
use db_study;
show databases;
show tables;
desc emp;                          -- 看表结构

-- 2. 建表（字段 类型 [约束] [comment]）
create table tb_user(
  id        int primary key auto_increment comment '主键',
  username  varchar(20) not null unique   comment '用户名',
  phone     char(11)                         comment '手机号',
  balance   decimal(10,2) default 0.00     comment '余额',
  create_time datetime default current_timestamp comment '创建时间'
) comment '用户表';

-- 3. 改表
alter table tb_user add email varchar(50);          -- 加字段
alter table tb_user modify phone varchar(20);       -- 改类型
alter table tb_user change phone mobile varchar(20); -- 改名+类型
alter table tb_user drop email;                    -- 删字段
alter table tb_user rename to tb_member;           -- 改表名
drop table if exists tb_member;                       -- 删表
类型占用/范围什么时候用
tinyint1 字节，-128~127状态、性别、年龄等小整数
int4 字节常规主键、数量、部门编号
bigint8 字节雪花 ID、订单号、超大计数
decimal(10,2)精确小数金额、薪资——不要用 float/double 存钱
char(11) / varchar(255)定长 / 变长手机号、身份证用 char；姓名、地址用 varchar
date / datetime日期 / 日期时间生日用 date；创建时间、更新时间用 datetime

DML · 增删改

写数据
-- 插入：指定字段（推荐，表结构变化不影响）
insert into emp(id, workno, name, gender, age, dept_id)
values (1,'E001','张三','男',25,10),
       (2,'E002','李四','女',28,20);

-- 插入：全字段（字段数、顺序必须与表结构一致）
insert into tb_user values (null,'王五','13800000000',100.00,now());

-- 修改：务必先 select 验证条件！
update emp set salary = salary + 500 where dept_id = 20;

-- 删除
delete from emp where id = 3;
truncate table emp;   -- 清空全表，自增归零，不可回滚
delete vs truncate：delete 可带 where、可回滚、自增不重置；truncate 只能清全表、不可回滚、自增重置、速度更快。 线上误删靠 binlog 恢复，别指望 rollback。

DQL · 查询

七天里的核心，占工作量 70%+

先背下这个完整模板，再往里填：

select   [distinct] 字段列表
from     表名
where    行级条件
group by 分组字段
having   分组后条件
order by 排序字段 [asc|desc]
limit    起始索引, 每页条数;
执行顺序（面试常问）： from → where → group by → having → select → order by → limit。 所以 where 里不能用聚合函数，having 里才能用；select 的别名一般不能在 where 中用。

1）基础查询与条件

select name, salary, salary * 12 as 年薪 from emp;
select distinct dept_id from emp;

select * from emp where age between 20 and 30;
select * from emp where dept_id in (10, 20);
select * from emp where name like '张%';      -- % 任意多个字符
select * from emp where name like '_三';       -- _ 单个字符
select * from emp where idcard is null;
select * from emp where gender = '女' and age < 30;
null 的坑：salary != 2000 查不出 salary 为 null 的行，因为 null 参与比较结果是 unknown。 要写 salary is null or salary <> 2000。同理 count(字段) 不统计 null，count(*) 统计所有行。

2）聚合、分组、排序、分页

-- 聚合：count / sum / avg / max / min
select count(*) 总人数, avg(salary) 平均薪资, max(salary) 最高薪资 from emp;

-- 分组 + 分组后筛选
select dept_id, count(*) 人数, avg(salary) 平均薪资
from emp
where age >= 20                 -- 分组前过滤
group by dept_id
having count(*) > 2            -- 分组后过滤
order by 平均薪资 desc;

-- 分页：第 n 页，每页 m 条 → limit (n-1)*m, m
select * from emp order by id limit 0, 10;   -- 第 1 页
select * from emp order by id limit 10, 10;  -- 第 2 页
where 和 having 怎么选：能放在 where 的条件就不要放 having。where 在分组前过滤行，能减少参与分组的数据量；having 是对聚合结果过滤。分组字段本身的条件，也可以写在 where 里。

05速查手册：多表 / 函数 / 约束 / 事务

这四块是“从会写到写对”的分水岭。多表查询尤其要多画图，先想清楚表之间怎么连，再动手写。

多表查询 · 连接与子查询

真实业务几乎全是多表
-- 笛卡尔积：不加连接条件 = 左表行数 × 右表行数（错误写法）
select * from emp, dept;

-- 内连接（隐式）：只保留两表都匹配上的行
select e.name 员工, d.name 部门
from emp e, dept d
where e.dept_id = d.id;

-- 内连接（显式）：推荐，语义更清楚
select e.name, d.name
from emp e inner join dept d on e.dept_id = d.id;

-- 左外连接：左表全保留，右表匹配不上补 null（统计“每个部门有几个人”用它）
select d.name 部门, count(e.id) 人数
from dept d left join emp e on e.dept_id = d.id
group by d.id, d.name;

-- 右外连接：右表全保留，实际项目中通常改写成左连接
select e.name, d.name
from emp e right join dept d on e.dept_id = d.id;

-- 自连接：同一张表起两个别名（员工-上级、分类-父分类）
select a.name 员工, b.name 上级
from emp a join emp b on a.manager_id = b.id;
选连接的口诀：要“两表都有才算”用内连接；要“主表一条都不能少”用左连接（主表放左边）； 要“同一张表自己跟自己比”用自连接。不确定时先画两张表的行，手动连一遍。 
-- 标量子查询：子查询返回一个值
select * from emp
where salary > (select avg(salary) from emp);

-- 列子查询：返回一列多行，配合 in / any / all
select * from emp
where dept_id in (select id from dept where name = '教研部');

-- 表子查询：把子查询结果当一张临时表，常用于“高于本部门平均薪资”
select e.name, e.salary, t.avg_sal
from emp e
join (select dept_id, avg(salary) avg_sal from emp group by dept_id) t
  on e.dept_id = t.dept_id
where e.salary > t.avg_sal;

-- 联合查询：上下拼接结果集，列数、类型要一致
select name, gender from emp where age < 25
union all                         -- union all 不去重，union 去重
select name, gender from emp where salary > 10000;

函数用在 where 里会导致索引失效：where date_format(entrydate,'%Y') = '2026' 无法走索引， 应改成 where entrydate >= '2026-01-01' and entrydate < '2027-01-01'。第七天学索引时会再遇到这个结论。

约束 · 把脏数据挡在门外

建表时顺手加，后面省很多事
create table tb_emp(
  id       int primary key auto_increment,
  name     varchar(20) not null,
  idcard   char(18) unique,
  age      tinyint unsigned check (age between 18 and 60),
  dept_id  int,
  constraint fk_emp_dept foreign key (dept_id) references dept(id)
);

-- 外键的级联行为（按业务选，不要默认全加）
alter table tb_emp add constraint fk_emp_dept
  foreign key (dept_id) references dept(id)
  on update cascade        -- 部门 id 变了，员工表跟着变
  on delete set null;      -- 部门删了，员工 dept_id 置空

alter table tb_emp drop foreign key fk_emp_dept;
约束作用注意
not null该字段不能为 null配合默认值使用，避免插入时报错
unique该列值不能重复，但可以有多个 null手机号、身份证、用户名常用
primary key唯一 + 非空，一张表只能有一个常用自增 int 或雪花 ID
default不传值时用默认值状态默认 0、余额默认 0.00
check限制取值范围（MySQL 8.0.16+ 才真正生效）年龄 18–60、金额不能为负
foreign key保证子表的值在父表中存在互联网常用“逻辑外键”，不建物理外键，避免级联锁表

事务 · 要么全成功，要么全失败

支付、库存、转账的底层
start transaction;                      -- 开启事务
update account set balance = balance - 100 where name = 'A';
update account set balance = balance + 100 where name = 'B';
commit;                                 -- 两步都成功才提交
-- rollback;                            -- 任何一步失败就回滚

ACID 四特性（用大白话记）

  • 原子性 A：转账扣钱和加钱是一个整体，不能只做一半。
  • 一致性 C：转账前后两人余额总和不变。
  • 隔离性 I：多个事务同时跑，彼此不偷看中间结果。
  • 持久性 D：commit 之后即使断电，数据也还在。

并发三大问题

  • 脏读：读到了别人还没提交的数据。
  • 不可重复读：同一事务内两次读同一行，结果不一样（别人 update 并提交）。
  • 幻读：同一事务内两次查同一范围，行数变多（别人 insert 并提交）。
隔离级别脏读不可重复读幻读说明
read uncommitted 读未提交可能可能可能几乎不用
read committed 读已提交不会可能可能Oracle 默认
repeatable read 可重复读不会不会可能（MVCC 基本规避）MySQL 默认
serializable 串行化不会不会不会性能最差，极少用
查看与设置隔离级别： select @@transaction_isolation; / set session transaction isolation level read committed;。 面试通常只要求说出四种级别、MySQL 默认是可重复读、以及各自能解决什么问题。

07新手最容易踩的 10 个坑

这些错误在课程作业和真实工作中都会出现，提前知道能省很多 debug 时间。

#错误写法 / 做法问题与正确做法
1where count(*) > 2where 执行在分组之前，此时还没有聚合结果。改用 having count(*) > 2。
2where salary = nullnull 不能用 = 比较，结果永远是 unknown。改用 is null / is not null。
3update emp set salary = 0;忘写 where 会改全表，线上属于事故。养成“先 select 验证、再 update”的习惯。
4select name, sum(salary) from emp;有聚合函数却没有 group by，MySQL 8 默认报错。除聚合字段外，其余字段必须出现在 group by 中。
5左连接的条件写在 where 里left join ... where d.id = 10 会把补 null 的行过滤掉，等价于内连接。右表条件应写在 on 后面。
6where price = 9.9（float 字段）浮点数存在精度误差，可能查不到。金额一律用 decimal。
7where id = (select dept_id from emp)子查询返回多行时用 = 会报错。根据语义改用 in，或加限制保证只返回一行。
8limit 100000, 10深分页会先扫描前 10 万行再丢弃。大数据量时改为“记住上一页最大 id，用 where id > ? limit 10”。
9建表不设主键、不指定字符集无主键影响复制与更新效率；字符集不统一会出现中文乱码。建库建表都显式写 utf8mb4。
10以为 commit 之后还能 rollbackcommit 是事务终点，提交后只能靠备份或 binlog 恢复。重要操作前先备份，生产环境谨慎执行 DML。
最后一句建议：七天结束后不要立刻去啃《高性能 MySQL》。先找一个小项目（比如课程设计、个人记账、爬虫数据入库）， 把建表、增删改查、多表统计完整写一遍，SQL 才算真正长在身上。之后再用进阶篇补索引与优化，顺序反过来会轻松很多。
